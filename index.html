    物流状态变更时，仅当事件类型也发生变更才触发推送。“在途中”归入发货事件。同一物流单的同一事件对同一接收账号只通知一次：已揽收已发送发货通知后，进入在途中不重复发送。其他类状态不生成推送任务，不增加H5未读通知；未知状态默认不推送。例：已揽收→在途中，事件均为发货，不推送；在途中→同城派送中，发货变为派送，推送一次；异常→派送→异常，异常已通知过则不再通知。首次同步以空状态作为比较基线，识别到有效事件时按相同规则判断。

    闪购运营商-更新说明

    PRD v1.3 · 更新日期：2026-09-21 · 适用对象：产品、开发、测试

    本说明覆盖闪购运营商管理、客户详情“已开通业务”的运营商身份联动，以及运营商绑定门店数量统计。以下页面规则为本次验收依据。

    1. 变更范围2. 业务流程3. 列表规则4. 新增规则5. 中台配置6. 客户详情联动7. 开发说明8. 测试验收

    1. 变更范围

    改动入口目标
    第一次：闪购运营商管理原型 → CRM系统 → 闪购 → 闪购运营商从已有客户中手动新增运营商，并为运营商单选配置海博中台。
    第二次：客户业务类型联动原型 → CRM系统 → 客户管理 → 客户详情 → 已开通业务客户进入运营商列表后，自动展示“闪购运营商”业务类型。
    本次补充：门店数量原型 → CRM系统 → 闪购 → 闪购运营商列表新增“门店数量”，统计每个运营商当前绑定的门店数。

    本次不增加运营商删除、停用、批量导入、批量配置和自动分配功能。原“闪购仓库存 → 闪购运营商配置”页面保留；新页面与该历史配置的迁移、联动不纳入本次已确认范围。

    2. 业务流程与状态

    已有客户 → 新增弹窗选中客户并确定 → 成为闪购运营商（待配置） → 手动选择一个海博中台并保存 → 已配置

    新增成功时立即触发客户详情业务类型展示，无需等待中台配置完成。

    客户状态运营商列表中台客户详情业务类型
    尚未添加不存在该客户不适用不显示“闪购运营商”
    已添加，待配置存在该客户，操作“配置中台”未配置显示“闪购运营商”
    已配置存在该客户，操作“修改中台”三个选项之一显示“闪购运营商”

    3. 运营商列表规则

    L01 查询：客户名称 / 客户编码支持去除首尾空格后的模糊匹配；海博中台支持“全部、未配置、海博万店、暗码无人仓、南京加减”。多个条件按“且”组合。点击搜索执行查询；关键词输入框支持回车查询。

    L02 重置：清空关键词，中台条件恢复“全部”，重新展示全部运营商。

    字段展示规则
    客户名称、客户编码取关联客户资料；运营商身份关联客户，不另建一份独立客户资料。
    联系人、手机号取客户资料对应信息，沿用现有手机号展示规则。
    门店数量位于手机号之后，显示当前绑定门店的去重数量，单位“家”；无绑定门店显示“0家”。字段只读，不支持手动修改。
    海博中台已配置时显示中台名称；未配置时显示“未配置”。
    配置结果展示列表不单独展示配置状态列；通过“海博中台”的名称或“未配置”及操作按钮区分。
    添加时间首次成为闪购运营商的时间；修改中台不改变此时间。
    操作待配置显示“配置中台”；已配置显示“修改中台”。

    L03 空结果：显示“暂无符合条件的闪购运营商”，提示调整筛选条件或新增运营商；底部数量为当前查询结果数。

    L04 门店数量统计：依据门店与闪购运营商的当前绑定关系，按运营商客户唯一标识关联，按门店唯一标识去重。一家门店存在多条商品、库存或渠道记录时仍只计一家。已解绑的历史关系不计入；门店绑定变化后重新查询或进入列表时获取最新数量。

    L05 统计独立性：数量不受运营商是否配置中台、所配置的中台或列表筛选条件影响。新增运营商无绑定门店时显示0家，已有绑定关系时按实际数量显示；修改中台不会改变绑定关系及门店数量。

    4. 新增闪购运营商

    A01 入口：点击列表上方“新增闪购运营商”，打开客户选择弹窗。只从已有客户中选择，不在此弹窗创建新客户。

    A02 客户选择：按客户名称或编码即时搜索；展示选择项、客户名称、客户编码、状态。一次单选一个客户。已是运营商的客户显示“已是运营商”，选择项禁用；其他客户显示“可添加”。无匹配结果提示调整搜索条件。

    A03 确认校验：未选择客户时提示“请选择客户”，保持弹窗；同一客户不得重复新增，重复时提示“该客户已是闪购运营商，请勿重复添加”。

    A04 新增成功：关联所选客户、记录添加时间，中台为空；关闭弹窗、重置列表查询并刷新。新增行海博中台显示“未配置”，提示“已新增闪购运营商，请配置海博中台”。客户详情立即具备“闪购运营商”业务类型。

    A05 取消：点击取消、关闭按钮、遮罩或按Esc退出，不新增客户、不建立运营商身份；再次打开弹窗不保留上次选择。

    5. 海博中台配置

    P01 配置弹窗：展示当前运营商的客户名称、客户编码，以及三个单选项：海博万店、暗码无人仓、南京加减。

    P02 数量限制：新增后的未配置状态允许中台为空；保存配置时必须选择一个中台。一个运营商不能同时配置多个中台；多个运营商可以配置到同一个中台。

    P03 默认值：首次配置不默认选中任何中台；修改时回显当前中台。未选择时提示“请选择一个海博中台”，不保存。

    P04 保存：所选中台替换原配置，更新列表中台名称和操作按钮，提示“海博中台配置已保存”。保存原值不会新增第二条配置；客户运营商身份与添加时间不变。

    P05 取消：取消、关闭、遮罩或Esc退出均不修改已保存配置。当前页面不提供清空中台的操作。

    6. 客户详情“已开通业务”联动

    B01 判断依据：使用客户唯一标识判断该客户是否存在于闪购运营商列表，不能按名称匹配，也不能以“是否已配置中台”代替运营商身份判断。

    B02 展示：已添加客户显示一个“闪购运营商”业务标签；未添加客户不显示。保留原有业务标签和样式，将新业务类型追加到现有业务列表。

    B03 刷新：新增成功后更新业务类型；每次打开或切换客户详情时重新依据当前客户判断，避免上一个客户的标签残留。重复打开不重复追加标签。

    B04 独立性：待配置、已配置、修改中台均保持运营商业务类型展示。该标签只展示业务身份，本次不增加标签点击、编辑或手动取消功能。

    7. 开发实现与边界

    以下是落地开发要求；接口路径、表名和具体字段名由开发按现有项目约定确定。

    数据 / 能力约束
    运营商与客户关系保存客户唯一标识，建立唯一约束；并发新增同一客户也只能成功建立一份运营商身份。
    中台配置使用单值字段或等价的一对一约束；允许未配置，非空时必须属于三个合法选项。服务端也应校验。
    门店数量列表查询返回各运营商当前绑定门店的去重计数；数据来源为门店绑定关系，不使用库存条数、中台全部门店数或手填数量。计数查询失败不得伪装成0，开发环境应提示加载失败并支持重试。
    客户业务类型以已保存的运营商身份为统一数据来源，保证运营商列表与客户详情一致，避免维护不同步的独立标记。
    查询与写入支持客户查询、运营商查询、新增、单中台修改；写入成功后刷新列表与客户业务信息。
    请求失败与重复提交开发时保存期间禁用重复提交；失败时保留原状态与用户输入并提示失败，只有服务端成功后才展示成功结果。
    权限与历史数据沿用CRM现有客户可见范围及操作权限；历史运营商是否迁入新列表、与库存配置如何映射需另行确认，不据此自动迁移。

    原型说明：当前为页面内存中的演示数据，刷新整个HTML会恢复示例；未接真实接口、数据库及权限系统。请求失败、并发唯一性与刷新后持久化需要在开发环境验收。

    入口：CRM系统 → 闪购 → 海博中台配置。列表固定展示海博万店、暗码无人仓、南京加减，字段包括海博中台、默认关联门店性质、更新时间、操作。

    N01 配置选项：点击“配置门店性质”打开弹窗，显示中台名称，通过复选框多选：店中店、形象店及专卖店、商圈联营店、仓中仓、24小时营业无人仓、24小时营业门店。

    N02 保存和回显：每个中台独立保存一组默认门店性质；再次编辑回显已保存项，保存时整体替换该中台的选择并去重，更新列表及更新时间。同一门店性质可被不同中台选择。

    N03 初始及清空：未指定预置值，原型中三个中台初始均“未设置”。本次按可选0至6项设计，全部取消后保存即清空默认性质，不表示关联全部性质。

    N04 取消：取消、关闭、遮罩或Esc退出均不保存本次勾选；重新打开回显上次保存值。

    N05 生效边界：本次管理中台的默认门店性质配置，不直接修改已有门店的性质、运营商绑定关系或门店数量。后续在哪个业务环节使用该默认配置、是否影响历史门店，需另行确定。本配置为多选，运营商选择中台仍为单选。

    开发说明：服务端按中台唯一标识保存性质集合，校验选项合法性并去重；保存失败保留原配置。当前HTML仅做内存演示，刷新整页恢复初始示例。

    验收：①六个选项完整；②同时选择多个后保存、回显一致；③切换中台配置互不覆盖；④全部取消后显示未设置；⑤取消修改保留原值；⑥多次勾选无重复标签；⑦配置前后运营商中台及门店数量不变；⑧开发环境验证保存失败及刷新后持久化。
